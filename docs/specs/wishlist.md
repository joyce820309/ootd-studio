# 選購清單、比較試搭與外部 AI

## 選購候選資料與狀態

- 狀態：考慮中 `considering`、準備購買 `ready`、已購買 `bought`、已放棄 `dropped`。「等待降價」已移除；migration 0024 把舊資料改為考慮中，資料庫 enum 的 `waiting` 值保留但前端不顯示、不寫入。
- `product_code` 儲存賣場商品編號；商品網址只存連結，不抓取網頁。僅在店家欄空白時，依已知 URL 網域推測店家。
- 類型規格、選項和推測方式見 [categories.md](categories.md)。
- `colors` 陣列元素可帶 `favorite: true` 表示最想要的顏色；整件候選最多一色為 true，未標記時比較表不替任何顏色加框。此旗標存在 `colors` JSONB，不增加獨立欄位；B7.1／BM19 表單可設定與取消。
- migration 0027 新增 `flat_measurements_size`，標記平放尺寸與拉伸值實際量測的尺碼。選購表單在平放尺寸區可填此欄；此尺碼必須是商品 `size` 可選尺碼之一，否則不套用合身判斷。
- migration 0022 支援 `primary_part`、`also_parts`、`colors` JSON 陣列及不限張數商品圖片；每張圖片仍須小於 10MB。`item_photos.color_family` 可標記圖片顏色。
- 移至已購買時，每個勾選顏色建立一件衣物；選購紀錄保留所有新衣物 ID 與完整資料。

## 清單篩選與選取模式（B7.2／BM19.1）

- 篩選依序為狀態、部位、類型；件數依上一層篩選結果計算。選取部位後，只在該部位有類型時顯示類型列。內搭不是部位，小可愛是上衣類型。
- 選取模式中點整張卡片即可勾選，不開啟詳情；一般模式點卡片開啟詳情。已選項目跨篩選保留。
- 全選只作用在目前篩選結果；部分選取顯示橫線。再次操作切換全選／取消目前篩選的選取。
- 桌面選取模式右側顯示「整理給 AI」面板；手機以底部工具列與 bottom sheet 呈現。
- 總件數需反映所有已選候選，並指出有幾件不在目前篩選中；「清除」清空所有已選項。

## 整理給 AI

- 平台不呼叫 AI，只把使用者選取的商品資訊整理成文字，供複製至外部 AI。
- 面板包含硬編碼範本、要包含的資料開關、即時預覽、字數和複製。範本管理頁尚未實作；新增範本前先沿用預設，未來另做「編輯範本」管理功能。
- 選購評估可納入名稱／價格、顏色／尺寸、材質、平放尺寸、體態、衣櫃同類與商品網址；勾選決定輸出項目。
- 同類衣物由候選的部位與類型篩選。體態資料必須遵守「我的」的「AI 使用體態資料」偏好；關閉時不可附上體態。
- 相關邏輯：`src/lib/wishlistAi.ts`；面板：`src/components/wishlist/WishlistAiPanel.tsx`；設計稿：`B-Wishlist-Select.dc.html`、`B-M-Wishlist-Select.dc.html`。

## 選購比較（B23／BM20）

比較頁只回答「這幾件買哪件」；混搭試穿移到搭配工作台，商品以 query 參數預先帶入。比較頁不放畫布、試穿面板或「放上試穿」按鈕。

### 資料模型

- 一件選購商品可同時屬於多個比較；同一比較不可重複放同一件。migration 0025 新增 `compare_group_items`，關聯欄位為 `group_id`、`wishlist_item_id`、`position`、`chosen_size`、`added_at`，主鍵為前兩欄。
- migration 0028 新增關聯層級的 `is_decided`；每個比較最多一件標為決定購買，與候選在其他比較的決定狀態分開。
- 比較表 `compare_groups` 使用 `name`、`archived_at`、`created_at`、`updated_at`；資料表沿用專案的 `owner_id` 權限欄位。既有 `budget` 欄位暫保留，避免丟失資料；後續如確認不再使用再另行清理。
- 刪除關聯或比較不刪除選購商品；刪除商品時由 FK cascade 刪除所有比較關聯。
- migration 0025 由既有 `wishlist_items.compare_group_id` 搬移所有同使用者關聯，檢查搬移筆數後移除舊欄位；跨使用者的歷史錯誤關聯會略過並發出 notice。
- 現有 `compare_group_closet_items` 暫保留，供舊流程／搭配工作台過渡；本階段 `compare_group_items` 只關聯選購商品。未來衣櫃對照第二階段再擴充，屆時需保證 wishlist／closet 關聯恰有一種。

### 路由與操作

- `/wishlist` 上方切換為「清單｜比較」。`/wishlist/compare` 導向最近更新且未封存的比較；沒有比較時顯示引導從清單選商品。
- `/wishlist/compare/:id` 顯示指定比較；舊網址 `/wishlist/compare?group=:id` 轉至新路徑。
- 可建立、改名、封存、刪除比較；可從比較中移除單件商品（只刪關聯），以及調整欄位順序與本比較採用的尺碼。
- 選取清單商品可開新比較（預設以最多的類型和件數命名）或加入一個既有未封存比較；完成後直接進入該比較。

### 比較表

- 桌面（B23 v2）：整頁只有一條捲軸，比較表不可放進固定高度＋`overflow:auto` 的容器，外層也不設 overflow。
  - 最多並排 5 件，欄寬平分、不左右捲；超過 5 件時表頭左欄出現「‹ 1–5 / N ›」一次換一組。「只看不一樣」只比這一組看得到的欄。
  - 頁首一列：清單｜比較、比較名稱（下拉選單：切換比較／新的比較／已封存）、改名、只看不一樣（開關，`role="switch"`）、整理給 AI、加入商品、⋯。不另設左側「我的比較」欄。
  - 商品列在頂端時：圖 124px、名稱兩行、價格；捲離頂端後以 IntersectionObserver 偵測，改顯示黏在頂端約 60px 的精簡列（36px 小圖、名稱一行、價格＋尺碼）。
  - 「就買這件」「拿去試搭」只放在表格最底下。欄名欄 128px，每列上下 9px。
  - 拖曳排序存回 `position`，排序鈕聚焦時可用左右鍵移動；移除只刪關聯。
- 手機（BM20）維持一次比兩欄、商品列 sticky，「只看不一樣」同樣用開關。
- 只看不同處時，某列所有欄位值（含標籤）相同就收起；提供還原全部列與收起列摘要。手機只比較目前兩欄。
- 比較欄依序呈現（B23／BM20 v3）：價格（只列售價，通常會湊免運，不列運費與含運總價）→ 商品頁尺寸表 → 尺寸 vs 我的身體（有平放尺寸才出現）→ 顏色 → 我的筆記 → 材質與版型 → 跟衣櫃 → 購買。最低售價標「最便宜」；搭配件數最多標「最好搭」。
- 價格、商品頁尺寸表、尺寸、顏色、筆記一律完整顯示；材質與版型、跟衣櫃、購買預設收起。收起處顯示斜紋橫條「還有 N 區收起來了：…」，點了展開；畫面右下角的懸浮展開鈕（B26 `components/ui/FloatToggle.tsx`）也能一次展開／收起。收起時捲回第一個被收起的區塊上緣；沒有可收起的區塊（例如都是空的被藏起來）時懸浮鈕不顯示；開啟對話框時懸浮鈕先藏起。
- 懸浮鈕位置：桌面 `right/bottom: 32px`；手機 `right: 12px`、`bottom` = 底部操作列高度 + 12px + safe-area。頁面底部加留白（桌面 96px、手機再加操作列與導覽列高度），最後一列不被蓋住。
- 每件比較商品都沒內容的列不顯示；區塊內沒有任何列時連標題整區不顯示。
- 材質與版型分成「成分／版型／彈性／季節／洗滌」各一列。成分有 `material_percentages` 時排成「聚酯 70%・羊毛 30%」，否則用 `material_composition` 原文，再退回 `material`。選購商品目前沒有版型、彈性、季節、洗滌欄位，這四列一律空白而不顯示；要顯示需先新增欄位。
- 商品的 `size_note` 在比較表為「商品頁尺寸表・原文照貼，不判斷」，排在價格下方，一律完整顯示（不截斷、不加漸層）；沿用商品詳情的備註格式呈現換行、條列與粗體；不可把整段備註誤標為「有貨」或當成單一庫存狀態。
- 尺寸鬆量與伸展判斷必須沿用 B20 現有函式（F×2、`STRETCH_COMFORT`）；沒有已核定的寬鬆分級或褲長常穿範圍判斷時，只顯示數字，不自行訂門檻。缺少既有衣櫃搭配／重複度計算時先留空。
- 重複度（`wishInsights`，`src/lib/wishlist.ts`）：只跟衣櫃中**同類型**、在衣櫃裡的單品比，再取顏色最接近的那件判斷高／中／低；候選沒有類型（手動未選、名稱也推不出）時才退回比同部位。衣櫃單品尚未存類型，以 `closetItemTypeOf` 依名稱、再依分類名稱推測，比對順序與選購候選相同。衣櫃沒有同類型時顯示「重複度低・衣櫃沒有〈類型〉」。
- `chosen_size` 預設為有標記的 `flat_measurements_size`；沒有對應尺碼量測時回退商品可選尺碼第一項。只有 chosen size 與量測尺碼一致時才顯示 B20 合身判斷；不一致或未知時保留尺寸數字，顯示灰色「這是 M 的尺寸，L 沒有資料」提示。
- 最想要的顏色依 `colors[].favorite` 標框；未標記時所有色點皆不加框，不以陣列順序推測。
- 「就買這件」把所選候選狀態改為既有 `ready`（準備購買），並只標記該比較關聯的 `is_decided`；不新增選購狀態。其他候選可逐一勾選改為既有 `dropped`（已放棄）；比較可選封存或保留。其他比較中的關聯不受狀態變更影響。
- 每欄「拿去試搭」連到現有搭配工作台並預先帶入該商品；不新增搭配頁。

### 加入商品與 AI

- 比較頁「加入商品」開挑選器：名稱／店家／編號搜尋；重用選購清單部位、類型、長度篩選並加狀態篩選。預設狀態為考慮中，部位／類型／長度依比較中最多的候選預選。
- 多選加入；目前比較已有的候選需顯示停用且勾選；其他比較中的候選標示所在比較。全選只作用於目前篩選且尚未加入的商品。
- 「貼網址」只作為新增選購與網域推測店家，不抓取網頁；儲存後自動加入目前比較。
- 比較的「整理給 AI」沿用 B7.2 面板與複製流程，範本為「比較」；按比較表順序整理價格、尺碼與既有判斷、材質、顏色、退換、衣櫃關係、筆記及體態數字。平台不呼叫 AI。
- 手機最多兩欄，左右切換時不得兩欄顯示同一件；加入商品與買入確認使用 bottom sheet。
- 比較設計稿：`design/general/B-Compare.dc.html`、`B-Compare-Picker.dc.html`；手機：`design/mobile/B-M-Compare.dc.html`、`B-M-Compare-Picker.dc.html`。
