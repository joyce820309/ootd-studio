# 選購清單、比較試搭與外部 AI

## 選購候選資料與狀態

- 狀態：考慮中 `considering`、準備購買 `ready`、已購買 `bought`、已放棄 `dropped`。「等待降價」已移除；migration 0024 把舊資料改為考慮中，資料庫 enum 的 `waiting` 值保留但前端不顯示、不寫入。
- `product_code` 儲存賣場商品編號；商品網址只存連結，不抓取網頁。僅在店家欄空白時，依已知 URL 網域推測店家。
- 類型規格、選項和推測方式見 [categories.md](categories.md)。
- `colors` 陣列元素可帶 `favorite: true` 表示最想要的顏色；整件候選最多一色為 true，未標記時比較表不替任何顏色加框。此旗標存在 `colors` JSONB，不增加獨立欄位；B7.1／BM19 表單可設定與取消。
- 一個顏色＝三個獨立欄位（B22 ⑤，`src/lib/wishColors.ts`，測試 `wishColors.test.ts`）：`colors` 每筆為 `{ id, name, name_custom, hex, family, family_custom, source: 'photo'|'palette', favorite }`。
  - 每筆以 `id` 為 key（不用名稱或 index）；新增、刪除、修改只動那一筆，不重排、不重算其他筆。
  - `hex` 只在照片重新取樣或在選色器點色票時改變；改名絕不改 hex。
  - `name`：使用者一編輯就 `name_custom=true`，之後重新取色或點色票都不覆蓋；`name_custom=false` 時取色／點色票帶入最接近的色票名當建議名，輸入框直接以建議名為預設文字（可在原字上增減，例：「灰」→「花灰」）並標「建議名，可直接改」；清空名稱回到 `name_custom=false`。
  - 選色器底部的名稱也可以直接改；改過（或這一色本來就是自訂名）後再從照片取色，名稱維持不變，套用時以 `name_custom=true` 寫回；清空則回到建議名。
  - `family`：色系（COLOR_FAMILIES 名稱，如「紫」「紅粉」），每次 hex 改變依 OKLab 最近色票自動歸類；列上顯示「歸類 X ▾」可手動改，改過 `family_custom=true` 不再自動覆蓋。重複度的顏色比較用 family（候選任一色與衣櫃單品同色系即算顏色重複，色碼距離只做同分排序）。目前清單沒有依顏色篩選的功能；之後加入時也用 family。
  - 舊資料 `{ family: 名稱, hex }` 讀取時轉換：舊 family 當名稱（是色票名者視為建議名，否則為自訂名），色系依 hex 歸類；存檔時寫成新格式，不需 migration。
  - 圖片對應的顏色（`item_photos.color_family`）仍存名稱；表單內以顏色 id 記錄，存檔時換成當下名稱，所以改名不會讓圖片掉標記。
  - 圖片顏色選單：「未標顏色」（新加入圖片的預設，存 `__untagged__`，買下時不帶到任何顏色）、「全色」（存 `null`，買下時帶到每一色；舊資料沒標顏色的圖片即為全色）、再來是各色。刪除某一色時，標記該色的圖片改為「未標顏色」；存的名稱對不到現有顏色時也視為未標顏色。介面不顯示全色／未標顏色的文字標籤。
- B7.1／BM19 顏色列：色塊（44px，只打開這一色的選色器）｜名稱輸入框（唯一一份名稱，平常無框線像文字、hover 淡框、focus 2px `--color-mist-deep`）＋下方小字「來源・歸類 X ▾」｜★ 最想要／☆｜×。HEX 不在列上顯示；色票格子不常駐，只出現在「＋ 新增顏色」或點色塊打開的選色器。
- migration 0027 新增 `flat_measurements_size`，標記平放尺寸與拉伸值實際量測的尺碼。選購表單在平放尺寸區可填此欄；此尺碼必須是商品 `size` 可選尺碼之一，否則不套用合身判斷。
- migration 0022 支援 `primary_part`、`also_parts`、`colors` JSON 陣列及不限張數商品圖片；每張圖片仍須小於 10MB。`item_photos.color_family` 可標記圖片顏色。
- 移至已購買時，每個勾選顏色建立一件衣物；選購紀錄保留所有新衣物 ID 與完整資料。

## 清單／比較共用頁首
- `/wishlist`、`/wishlist/compare(/:id)` 是 `components/wishlist/WishlistLayout.tsx` 的子路由：外框（`wishlist-shell`，寬 1360、同上緣）與頁首（`wishlist-bar`：「選購清單」斜貼標題＋清單｜比較分頁）切換分頁時不重繪、不跳動。
- 各頁用 `<WishlistBar>` 把自己的頁首控制項放進分頁右側（清單：統計、搜尋、選取、加入選購；比較：比較名稱選單、改名、狀態字、只看不一樣與操作鈕）。`mobileHidden` 讓手機不顯示共用頁首（比較頁、清單手機詳細）；`sidePanel` 在桌機抽屜開著時讓整頁讓出右側 520px。
- 頁面 h1 統一是共用頁首的「選購清單」；比較名稱為 h2（手機比較頁自己的頁首仍以比較名稱為 h1）。

## 清單預覽面板與完整頁面（B7／B7.3／BM19.2）

- `/wishlist?item=:id` 是清單右側的預覽面板；右上角依序為「開完整頁面 ↗」「編輯」「⋯」。「放棄購買」（已放棄時為「重新考慮」）與刪除收進 ⋯（`components/wishlist/WishItemMoreMenu.tsx`），面板底部動作列只留移至已購買、加入比較等主要動作。手機版的返回列右側放 ↗ 圖示與 ⋯。
- 預覽面板的狀態改成「準備購買」（或從準備購買改回考慮中）與比較頁的「準備購買」走同一流程（`useBasket.toggleReady`）：第一次準備購買寫入預設明細（最想要的顏色 × 1 × 原價），立即進採購籃；準備購買時狀態列下方顯示顏色 × 件數 × 單價編輯（`BuyLinesEditor`），改了直接存並更新採購籃件數。
- 完整頁面 `/wishlist/:id`（`src/pages/WishlistItemPage.tsx`）：從清單預覽面板與比較頁預覽抽屜的「開完整頁面 ↗」以新分頁打開（`target="_blank" rel="noopener"`，`components/wishlist/OpenFullPageLink.tsx`），原頁面不動。「← 選購清單」回 `/wishlist?item=:id`。
- 桌機：左側照片區（主圖 4:5、寬約 640、往下捲時 sticky；左側直排縮圖 76×96；←／→ 鍵與左右按鈕切換；放大鏡在主圖右上、張數在左下；放大鏡或點主圖開全螢幕檢視，可左右滑、Esc 關）。照片欄與細項間距 40px，留空間給跨出照片的紙膠帶。右側細項分兩欄（容器寬 ≥560px 時）：左欄顏色、材質（下半部合併「特徵」）、比較・衣櫃、AI 看過的提醒；右欄商品頁尺寸表、平放尺寸＋合身判斷、我的筆記。目標是 1440×900 一個畫面看得到照片和全部細項，方便截圖。
- 桌機頂部：「← 選購清單」＋部位・類型・長度；右側「加入比較 ▾」「編輯」「⋯」。已購買改為「到衣櫃查看」，不能編輯。
- 手機：照片滿版 4:5 可左右滑，上方浮著 ←、編輯、⋯；下方一排縮圖。細項依序為顏色、商品頁尺寸表、平放尺寸、材質、我的筆記、特徵（手機不併進材質）、比較、AI 看過的提醒。底部固定「加入比較 ▾」與「準備購買」開關，和標題上方的狀態膠囊連動（已放棄改為「重新考慮」，已購買改為「到衣櫃查看」）。
- 狀態膠囊：標題上方「● 狀態 ▾」，點開選單（`role="menuitemradio"`）直接切換：考慮中／準備購買（小說明「進採購籃」）／已購買（「會開移至衣櫃」）／已放棄（「可再改回」）。膠囊顏色跟著狀態：考慮中 tile／ink-2、準備購買 sage-soft／status-ok-fg、已購買 mist-soft／mist-ink、已放棄 rose-soft／rose-deep。
  - 準備購買、以及從準備購買改回考慮中，走採購籃開關（`useBasket.toggleReady`），和手機底部開關同步；選「已購買」開「移至已購買」對話框（`BoughtDialog`）；其他改用 `setWishlistStatus`。
  - 已購買後衣物已經建立，膠囊只顯示、不能再改（目前實作的決定，設計稿沒有說明）。
- 顏色與照片連動（只在有照片標了顏色時啟用）：
  - 有標記照片的顏色是可點的膠囊（`aria-pressed`）：點了只顯示那色的照片（縮圖、←／→、張數、放大檢視都只算那幾張），從第一張開始；主圖左上角出現深色「只看「X」×」，張數變成「1 / 2・X」；再點同一色或按 × 回到全部。選中樣式是深色膠囊、色塊外圈一圈紙色。
  - 沒有標記照片的顏色是純文字（無外框）：點了維持顯示全部，下方提示「「X」還沒有標記照片，顯示全部照片。」不顯示張數數字。
  - 比對方式：照片的 `color_family` 存顏色名稱，等於顏色名稱就算同色。**與設計規格不同**：設計稿寫 `photo.color_id` 對應 colors 的 id，目前資料庫沒有這個欄位，仍用名稱比對（改名時表單會同步更新照片標記）。
- 照片顏色標籤（B27，`components/ui/PhotoColorTag.tsx`）：有標顏色的照片貼一段半透明紙膠帶，寫小色點＋色名（霞鶩漫黑 18px，手機 16px）。依商品 id 算出固定的膠帶顏色（燕麥黃、霧藍、鼠尾草、蜜桃粉、薰衣草）、角度（-8°~-3° 或 3°~7°，同一件每張微調）與位置（右下角斜貼／壓在下緣／右緣直貼；手機只用壓在下緣）。照片外框不裁切，圓角放在內層。縮圖不貼膠帶，右下角放 14px 色點（2px 紙色外圈）。膠帶 `aria-hidden`，主圖 alt 寫「名稱・色名・第 N 張」。目前只用在完整頁面。
- 三張便利貼（本體不旋轉，見 [components.md](components.md)）：商品頁尺寸表＝薰衣草方格紙（22px 一格、格線很淡、貼蜜桃粉膠帶、不摺角，標「原文照抄」）；我的筆記＝霧藍、貼燕麥黃膠帶；AI 看過的提醒＝鼠尾草、貼霧藍膠帶。
- AI 看過的提醒：記「下單前要確認的風險」（我的筆記記喜好）。資料存 `wishlist_items.ai_review`（文字，「- 」開頭為清單）與 `ai_reviewed_at`，標題旁顯示「11/20 貼上」。按鈕「整理給 AI」複製這件的資料（沿用整理給 AI 的預設欄位，並請 AI 用條列回覆）；「貼上新回覆」開對話框貼上，清空後儲存＝清除。平台不呼叫 AI。已購買且沒有內容時不顯示。
- 合身判斷沿用比較頁的 B20 判斷（`buildSizeRows`＋`judgeLabel`），沒有結論的部位不顯示。

## 材質比例（全專案統一）

- 共用函式 `src/lib/materialMix.ts`（測試 `materialMix.test.ts`），元件 `components/ui/MaterialMix.tsx`。
- 一律依 % 從多到少排；沒有 `material_percentages` 時會從 `material_composition` 原文抓「棉 60%」片段。
- 完整頁面、清單預覽面板、比較預覽、衣物詳細：10px 比例條（各段間隔 2px）＋圖例「● 名稱 …… 85%」。
- 比較表「成分」列、整理給 AI、踩雷覆盤：一行「聚酯纖維 85%・彈性纖維 15%」。
- 清單卡片：只寫前兩種並用短名「聚酯 85%・彈性 15%」（「其他」不列）。
- 沒填 %：只列名稱、不畫比例條。加總不到 100：補灰色「其他 X%」（有選了材質但沒填 % 的項目時不補，避免重複）。
- 色點用材質色，見 [managed-lists.md](managed-lists.md)。

## 清單篩選與選取模式（B7.2／BM19.1）

- 篩選依序為狀態、部位、類型；件數依上一層篩選結果計算。選取部位後，只在該部位有類型時顯示類型列。內搭不是部位，小可愛是上衣類型。
- 選取模式中點整張卡片即可勾選，不開啟詳情；一般模式點卡片開啟詳情。已選項目跨篩選保留。
- 全選只作用在目前篩選結果；部分選取顯示橫線。再次操作切換全選／取消目前篩選的選取。
- 桌面選取模式右側顯示「整理給 AI」面板；手機以底部工具列與 bottom sheet 呈現。
- 總件數需反映所有已選候選，並指出有幾件不在目前篩選中；「清除」清空所有已選項。

## 整理給 AI

- 平台不呼叫 AI，只把使用者選取的商品資訊整理成文字，供複製至外部 AI。
- 面板包含硬編碼範本、要包含的資料開關、即時預覽、字數和複製。範本管理頁尚未實作；新增範本前先沿用預設，未來另做「編輯範本」管理功能。
- 選購評估可納入名稱／價格、顏色／尺寸、材質、平放尺寸、體態、衣櫃同類與商品網址；勾選決定輸出項目。
- 同類衣物由候選的部位與類型篩選。體態資料必須遵守「我的」的「AI 使用體態資料」偏好；關閉時不可附上體態。
- 相關邏輯：`src/lib/wishlistAi.ts`；面板：`src/components/wishlist/WishlistAiPanel.tsx`；設計稿：`B-Wishlist-Select.dc.html`、`B-M-Wishlist-Select.dc.html`。

## 選購比較（B23／BM20）

比較頁只回答「這幾件買哪件」；混搭試穿移到搭配工作台，商品以 query 參數預先帶入。比較頁不放畫布、試穿面板或「放上試穿」按鈕。

### 資料模型

- 一件選購商品可同時屬於多個比較；同一比較不可重複放同一件。migration 0025 新增 `compare_group_items`，關聯欄位為 `group_id`、`wishlist_item_id`、`position`、`chosen_size`、`added_at`，主鍵為前兩欄。
- migration 0028 新增關聯層級的 `is_decided`；B23.3 改版後前端不再寫入或顯示，欄位與 RPC 保留以相容舊資料。
- 比較表 `compare_groups` 使用 `name`、`archived_at`、`created_at`、`updated_at`；資料表沿用專案的 `owner_id` 權限欄位。既有 `budget` 欄位暫保留，避免丟失資料；後續如確認不再使用再另行清理。
- 刪除關聯或比較不刪除選購商品；刪除商品時由 FK cascade 刪除所有比較關聯。
- migration 0025 由既有 `wishlist_items.compare_group_id` 搬移所有同使用者關聯，檢查搬移筆數後移除舊欄位；跨使用者的歷史錯誤關聯會略過並發出 notice。
- 現有 `compare_group_closet_items` 暫保留，供舊流程／搭配工作台過渡；本階段 `compare_group_items` 只關聯選購商品。未來衣櫃對照第二階段再擴充，屆時需保證 wishlist／closet 關聯恰有一種。

### 路由與操作

- `/wishlist` 上方切換為「清單｜比較」。`/wishlist/compare` 導向最近更新且未封存的比較；沒有比較時顯示引導從清單選商品。
- `/wishlist/compare/:id` 顯示指定比較；舊網址 `/wishlist/compare?group=:id` 轉至新路徑。
- 可建立、改名、封存、刪除比較；可從比較中移除單件商品（只刪關聯），以及調整欄位順序與本比較採用的尺碼。
- 選取清單商品可開新比較（預設以最多的類型和件數命名）或加入一個既有未封存比較；完成後直接進入該比較。

### 比較表

- 桌面（B23 v2）：整頁只有一條捲軸，比較表不可放進固定高度＋`overflow:auto` 的容器，外層也不設 overflow。
  - 最多並排 5 件，欄寬平分、不左右捲；超過 5 件時表頭左欄出現「‹ 1–5 / N ›」一次換一組。「只看不一樣」只比這一組看得到的欄。
  - 頁首一列：清單｜比較、比較名稱（下拉選單：切換比較／新的比較／已封存）、改名、只看不一樣（開關，`role="switch"`）、整理給 AI、加入商品、⋯。不另設左側「我的比較」欄。
  - 商品列在頂端時：圖 124px、名稱兩行、價格；捲離頂端後以 IntersectionObserver 偵測，改顯示黏在頂端約 60px 的精簡列（36px 小圖、名稱一行、價格＋尺碼）。
  - 「準備購買」開關與「拿去試搭」只放在表格最底下。欄名欄 128px，每列上下 9px。
  - 拖曳排序存回 `position`，排序鈕聚焦時可用左右鍵移動；移除只刪關聯。
- 手機（BM20）維持一次比兩欄、商品列 sticky，「只看不一樣」同樣用開關。
- 只看不同處時，某列所有欄位值（含標籤）相同就收起；提供還原全部列與收起列摘要。手機只比較目前兩欄。
- 比較欄依序呈現（B23／BM20 v3）：價格（只列售價，通常會湊免運，不列運費與含運總價）→ 商品頁尺寸表 → 尺寸 vs 我的身體（有平放尺寸才出現）→ 顏色 → 我的筆記 → 材質與版型 → 跟衣櫃 → 購買。最低售價標「最便宜」；搭配件數最多標「最好搭」。
- 「重複」先限制同類型，再以顏色、材質、可比較的長度、單選特徵及多選特徵重疊比例提供固定規則結論「很像／有點像／不太像」。缺少任何一側資料的維度略過，不推斷為不同；跳過後依據不足顯示「依據較少」，不顯示相似百分比。顯示「同：…／不同：…」依據；若最接近的衣櫃單品沒有特徵，提供直達該衣物編輯表單的「幫衣櫃單品補特徵」連結。
- 商品頁尺寸表中的商品名稱可在不換頁的快速預覽中查看；預覽位置與 B23.2／BM20.2 規格見 [design-map.md](../design-map.md)。
- 價格、商品頁尺寸表、尺寸、顏色、筆記一律完整顯示；材質與版型、跟衣櫃、購買預設收起。收起處顯示斜紋橫條「還有 N 區收起來了：…」，點了展開；右下角懸浮按鈕組（B26 `components/ui/FloatActions.tsx`）的展開鈕也能一次展開／收起。收起時捲回第一個被收起的區塊上緣；沒有可收起的區塊（例如都是空的被藏起來）時展開鈕不顯示。
- B26 懸浮按鈕組：三顆 44×44、圓角 8px 的圖示鈕，由上到下為回到頂端、展開／收起、採購籃，間距 8px、靠右；沒出現的不佔位。
  - 回到頂端：往下捲超過一個視窗高度才淡入；平滑捲到頂端（減少動態時直接跳），焦點移到頁面 h1。
  - 展開／收起：有收起的區塊才出現；展開後換朝上雙箭頭、霧藍底；加 `aria-expanded`。
  - 採購籃：深色底、燕麥色圖示，右上角 18px 角標只放件數，不顯示金額（金額只在採購籃抽屜看）；有準備購買才出現，點了打開採購籃抽屜。
  - aria-label：「回到頂端」「展開其餘 N 區」／「收起後面幾區」「打開採購籃，N 件」；角標與提示文字 `aria-hidden`。滑過或鍵盤焦點時左側 10px 出現深色提示，觸控裝置不顯示。
  - 打開採購籃抽屜、預覽抽屜、對話框（清單頁另含選取模式）時整組隱藏。
- 懸浮按鈕組位置：桌面 `right/bottom: 24px`；手機 `right: 12px`、`bottom` = 底部操作列高度 + 12px + safe-area（頁面以 `--float-actions-bottom` 提供）。頁面底部留白桌面 80px、手機再加操作列與導覽列高度，最後一列不被蓋住。
- 每件比較商品都沒內容的列不顯示；區塊內沒有任何列時連標題整區不顯示。
- 材質與版型分成「成分／版型／彈性／季節／洗滌」各一列。成分依「材質比例」規則排成一行「聚酯纖維 70%・羊毛 25%・其他 5%」。選購商品目前沒有版型、彈性、季節、洗滌欄位，這四列一律空白而不顯示；要顯示需先新增欄位。
- 商品的 `size_note` 在比較表為「商品頁尺寸表・原文照貼，不判斷」，排在價格下方，一律完整顯示（不截斷、不加漸層）；沿用商品詳情的備註格式呈現換行、條列與粗體；不可把整段備註誤標為「有貨」或當成單一庫存狀態。
- 快速預覽（B23.2／BM20.2，`components/wishlist/ComparePreview.tsx`）：點欄頂名稱或圖片打開，不換頁。網址加 `?preview=:id`，重新整理後還在；從表格打開時推一筆瀏覽紀錄，「上一頁」先關預覽，之後的切換不再增加紀錄。
  - 桌機：右側抽屜寬 520px、全高、不加灰底；視窗 ≥1200px 時比較表讓出右側 520px 不被蓋住，小於 1200px 時抽屜蓋在表上並加淡灰底。手機：Bottom Sheet，top 40px，加灰底、背景不捲。
  - 切換：‹ ›、上方縮圖列、鍵盤 ←／→（循環；焦點在輸入框、選單或排序鈕時不攔）、點表格欄頂名稱或精簡列。Esc 關閉。預覽中的那欄加 2px 深色框並標「預覽中」。
  - 內容：照片（主圖＋縮圖）、狀態、名稱、價格、店家、加入日期、顏色、商品頁尺寸表、平放尺寸、我的筆記；沒資料的區塊不顯示。
  - 比較封面：預覽裡有兩張以上照片時，可把目前看的這張「設為比較封面」，欄頂、精簡列與手機欄位改用這張；已是封面時可「改回商品原本的封面」。只存在這個比較的關聯（`compare_group_items.cover_photo_path`，migration 0031），不改選購清單的封面，同一件在不同比較可用不同封面。
  - 右上角：開完整頁面（新分頁開 `/wishlist/:id`，比較頁不動）、編輯（B7.1 對話框，存檔後表格與預覽一起更新；已購買不顯示）、關閉。手機為 ↗ 圖示、編輯、關閉。
  - 預覽也顯示材質比例（比例條＋圖例）。
  - 底部：從這個比較移除（僅桌機）、拿去試搭、「準備購買」開關（與欄底同一個開關）。手機只放拿去試搭與準備購買；手機移除用欄頂 ×。
  - 有了預覽，欄頂縮圖上的編輯鉛筆拿掉，只留 ⋮⋮ 與 ×；編輯從預覽進。預覽開著時不顯示 B26 懸浮按鈕組。
- 尺寸鬆量與伸展判斷必須沿用 B20 現有函式（F×2、`STRETCH_COMFORT`）；沒有已核定的寬鬆分級或褲長常穿範圍判斷時，只顯示數字，不自行訂門檻。缺少既有衣櫃搭配／重複度計算時先留空。
- 重複度（`wishInsights`，`src/lib/wishlist.ts`）：只跟衣櫃中**同類型**、在衣櫃裡的單品比，再取顏色最接近的那件判斷高／中／低；候選沒有類型（手動未選、名稱也推不出）時才退回比同部位。衣櫃單品尚未存類型，以 `closetItemTypeOf` 依名稱、再依分類名稱推測，比對順序與選購候選相同。衣櫃沒有同類型時顯示「重複度低・衣櫃沒有〈類型〉」。
- `chosen_size` 預設為有標記的 `flat_measurements_size`；沒有對應尺碼量測時回退商品可選尺碼第一項。只有 chosen size 與量測尺碼一致時才顯示 B20 合身判斷；不一致或未知時保留尺寸數字，顯示灰色「這是 M 的尺寸，L 沒有資料」提示。
- 最想要的顏色依 `colors[].favorite` 標框；未標記時所有色點皆不加框，不以陣列順序推測。
- 準備購買與採購籃（B23.3／BM20.3）：
  - 每欄底部是「準備購買」開關（`aria-pressed`），取代原本的「就買這件」與其確認對話框。開＝狀態改 `ready`；沒有購買明細時建立一行「最想要的顏色（沒有就第一個顏色）× 1 × 原價」。關＝改回 `considering`，明細保留，再打開時沿用。一個比較可同時開好幾欄；已購買的欄顯示「已購買」不可切換。
  - 購買明細存在 `wishlist_items.buy_lines`（jsonb，`[{ color_name, hex, qty, unit_price }]`，migration 0029）。小計 = Σ qty × unit_price；單價可直接填活動後的價格。平台不做任何滿額或活動規則。
  - 桌機：開啟的那欄下方顯示明細編輯區：每色一行（色點、色名、× 移除（至少留一行）、件數 stepper 最小 1、單價輸入，離開欄位或 Enter 才存），「＋ 加一色」只列這件商品 colors 裡還沒加的顏色，下面是小計件數與金額。手機欄下只放開關，明細在採購籃裡編輯。
  - 採購籃入口：比較頁與 `/wishlist` 清單頁右下角 B26 懸浮按鈕組的採購籃鈕（只顯示件數角標）；有準備購買的商品才顯示，點了打開採購籃抽屜。總金額、目標進度只在抽屜裡看。
  - 採購籃：桌機右側抽屜寬 470px（≥1200px 時比較表讓出右側，小於 1200px 加淡灰底），手機 Bottom Sheet（top 70px）。採購籃與快速預覽不同時開，打開一個會關掉另一個。
    - 依比較分組：同一件在好幾個比較裡時，只列在最近更新的比較；不在任何比較裡的放「其他」。
    - 每件顯示縮圖、名稱、顏色 × 件數（同單價且多件時加「各 $單價」，單價不同時逐色列出）、小計。手機可直接改件數、單價、加減顏色。
    - 「目標金額」選填，存在 `profiles.shopping_target`（整數，可清空；migration 0029），只用來算還差多少。
    - 底部：共 X 款・Y 件、總金額、進度條、「複製清單」、「買好了，移到已購買…」。後者可勾選要移哪幾件、選購買日期，接既有 `markWishlistBought`：依明細每一件建立一件衣物，實付價格記為該行單價，顏色依明細帶入。
    - 「複製清單」純文字：每款一行 `名稱 色×件數 色×件數 $小計`，最後一行 `共 X 款 Y 件 NT$總額`。
  - 「收尾這個比較…」：桌機在標題列右側，手機在 ⋯ 選單。列出這個比較中沒開準備購買、也還沒買的商品，預設勾選「改成已放棄」（已放棄的不預設勾）；另選比較封存或先留著。
- 每欄「拿去試搭」連到現有搭配工作台並預先帶入該商品；不新增搭配頁。

### 加入商品與 AI

- 比較頁「加入商品」開挑選器：名稱／店家／編號搜尋；重用選購清單部位、類型、長度篩選並加狀態篩選。預設狀態為考慮中，部位／類型／長度依比較中最多的候選預選。
- 多選加入；目前比較已有的候選需顯示停用且勾選；其他比較中的候選標示所在比較。全選只作用於目前篩選且尚未加入的商品。
- 「貼網址」只作為新增選購與網域推測店家，不抓取網頁；儲存後自動加入目前比較。
- 比較的「整理給 AI」沿用 B7.2 面板與複製流程，範本為「比較」；按比較表順序整理價格、尺碼與既有判斷、材質、顏色、退換、衣櫃關係、筆記及體態數字。平台不呼叫 AI。
- 手機最多兩欄，左右切換時不得兩欄顯示同一件；加入商品與買入確認使用 bottom sheet。
- 比較設計稿：`design/general/B-Compare.dc.html`、`B-Compare-Picker.dc.html`；手機：`design/mobile/B-M-Compare.dc.html`、`B-M-Compare-Picker.dc.html`。
