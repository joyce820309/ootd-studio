# 部位、類型與分類

## 衣物部位

`Slot` 目前固定為六種：外套 `outer`、上衣 `top`、下身 `bottom`、鞋子 `shoes`、包包 `bag`、配件 `acc`。今日搭配必選部位為上衣、下身、鞋子。部位中繼資料以 `src/lib/slots.ts` 為唯一來源；分類不要寫死在 UI，由新使用者 trigger 建立預設分類。

目前沒有「連身」部位；如需增加，須先評估資料庫分類、今日搭配、尺寸欄位與既有資料，不可只在篩選 UI 增加選項。（見文末「待決定」）

## 怎麼判斷部位（有疑問時照這個順序）

1. 會疊在另一件上衣外面穿的 → 外套。今日搭配的「上衣」只有一格，疊穿的那層必須在「外套」。例：毛絨背心、鋪棉背心、針織背心、披著穿的開衫。
2. 單穿，或穿在最裡面的 → 上衣。例：小可愛、細肩帶、T 恤。
3. 兩種穿法都常見 → 主要部位選最常的那種，另一種放 `also_parts`。例：薄羅紋開衫扣起來單穿 → 上衣，也可以當外套。
4. 「內搭」不是部位，也不是類型，是穿法；用 `also_parts` 或備註處理。
5. 襪套、袖套這類穿戴配件 → 配件・襪子・襪套。

## 類型（garment_type）

類型為選填；未選時存 `null`，篩選顯示為「未分類」。代碼一旦上線就不改名，只改顯示文字。

- 上衣 `top`（選購候選已實作，migration 0024）
  - `tee` T 恤・大學 T・帽 T
  - `knit` 針織・毛衣
  - `vest` 背心・小可愛（只放單穿或穿最裡面的；毛絨／鋪棉／針織背心請歸外套 `gilet`）
  - `shirt` 襯衫
  - `thermal` 發熱衣（穿在其他上衣裡面，不外露；暫行做法見文末「穿在裡面的保暖層」）
- 外套 `outer`（選購候選已實作）
  - `cardigan` 開衫・針織
  - `blazer` 西裝
  - `jacket` 夾克（牛仔、皮衣、飛行、襯衫外套）
  - `coat` 大衣・風衣
  - `puffer` 羽絨・鋪棉（含長版羽絨、派克大衣等寒地厚外套）
  - `gilet` 背心外套（毛絨、鋪棉、針織背心）
  - `outdoor` 機能外套（Gore-Tex、防水、防風、衝鋒衣、騎車外套）
  - 外套看「主要靠什麼」：防水防風的外層殼 → 機能外套；靠羽絨或化纖填充保暖 → 羽絨・鋪棉；羊毛等厚呢料 → 大衣・風衣。兩種都有（例：防水羽絨）時選最常用的情境。
- 下身 `bottom`（選購候選已實作）
  - `pants` 褲子（休閒褲、西裝褲、運動褲等非寬版褲型）
  - `wide` 寬褲（寬褲、闊腿褲、寬版褲；寬版牛仔褲歸 `jeans`）
  - `jeans` 牛仔褲
  - `skirt` 裙子（含褲裙）
  - `leggings` 內搭褲・瑜珈褲（會外露，單穿或配長版上衣、洋裝）
  - `thermal` 發熱褲（穿在其他褲子裡面，不外露）
  - `outdoor` 機能褲（防水褲、雪褲、衝鋒褲）
  - 短褲、短裙不另設類型：用「褲子／寬褲／牛仔褲／裙子＋長度・短」，見下方「長度」
- 鞋子 `shoes`（選購候選已實作）
  - `sneakers` 運動鞋
  - `flats` 平底・樂福
  - `boots` 長靴・雪靴
  - `sandals` 涼鞋
  - `heels` 跟鞋
- 包包 `bag`（選購候選已實作）
  - `tote` 托特・肩背
  - `crossbody` 斜背
  - `backpack` 後背
  - `clutch` 手拿
  - `mini` 小廢包（只裝手機、鑰匙、卡片的迷你包）
- 配件 `acc`（選購候選已實作）
  - `hat` 帽子
  - `scarf` 圍巾・披肩
  - `belt` 皮帶
  - `socks` 襪子・襪套
  - `necklace` 項鍊




## 選購候選的部位與類型

- `wishlist_items.primary_part` 是主要部位與分類、尺寸欄位依據；`also_parts` 可複選，讓候選可在多個今日搭配部位被找到（migration 0022）。
- 部位不是類型；「內搭」不是部位。小可愛歸「上衣 ・ 背心・小可愛」；毛絨背心歸「外套 ・ 背心外套」。
- `wishlist_items.garment_type` 儲存類型代碼（migration 0024）。
- 類型選項目前已用於選購候選表單、篩選、卡片與 AI 文字；衣櫃衣物（items）尚未儲存類型，未來需使用同一組代碼並新增 migration。
- 表單未手動選類型時，篩選與 AI 文字可依商品名稱推測類型；明確儲存值優先。
- 新增、改名或刪除類型時，檢查選購表單、篩選計數、候選卡片、外部 AI 文字、資料存取、示範資料及 migration。

## 篩選列

- 第一排狀態（單選）、第二排部位；選了幾個部位就出現幾排「類型」。
- 部位、類型、長度都可多選；每排的「全部」＝清空該排。網址以逗號分隔，類型記為「部位:類型」（例：`?part=bottom,top&type=bottom:wide,bottom:pants&length=short`）。
- 類型按部位各自篩：選「下身・寬褲」不影響同時選的上衣（上衣沒選類型＝上衣全部）。
- 選了下身、且沒選下身類型或選的類型有長度時，再接一組「長度」（短／中／長）；長度只篩下身。
- 件數為 0 的類型不顯示（「全部」除外）；有 `null` 資料時才顯示「未分類 N」。
- 取消某個部位時，只清掉該部位的類型；取消下身時一併清掉長度。共用邏輯：`src/lib/wishlist.ts` 的 `applyWishFacets`、`normalizeFacets`。

## 分類資料原則

- `categories` 由使用者擁有；新增分類時遵循 Supabase RLS 規則，見 [data-storage.md](data-storage.md)。
- 衣物的分類與部位可分離；如衣物引用的分類可對應不同部位，使用 `categorySlot` 等現有型別欄位，不要假定分類名稱唯一決定部位。
- 共用型別在 `src/types.ts`，部位定義在 `src/lib/slots.ts`。

## 長度（garment_length）

- 可和類型組合篩選，例：裙子＋短。
- 適用類型：`pants`、`wide`、`jeans`、`skirt`、`leggings`；其他下身類型不顯示長度。
- 值：`short` 短、`mid` 中、`long` 長；選填。
- 顯示名稱由「類型＋長度」組合，不另存：

| 類型 | short | mid | long | 沒選長度 |
|---|---|---|---|---|
| `pants` | 短褲 | 七分褲 | 長褲 | 褲子 |
| `wide` | 寬版短褲 | 寬版七分褲 | 寬褲 | 寬褲 |
| `jeans` | 牛仔短褲 | 七分牛仔褲 | 牛仔長褲 | 牛仔褲 |
| `skirt` | 短裙 | 中長裙 | 長裙 | 裙子 |
| `leggings` | 短版內搭褲 | 七分內搭褲 | 內搭褲 | 內搭褲 |

- 篩選列：選了下身時，類型後面接長度（短／中／長），例：裙子＋短＝只看短裙；只選「短」＝短褲＋短裙一起看。
- 選購候選的 `garment_length` 由 migration 0026 儲存；新增／編輯選購候選時僅在適用的下身類型顯示短／中／長。既有未知值保留 `null`，不依名稱猜測長度。

- 發熱褲（下身 `thermal`）與發熱衣（上衣 `thermal`）穿在其他衣物裡面，不該佔用今日搭配的「上衣」「下身」那一格。
