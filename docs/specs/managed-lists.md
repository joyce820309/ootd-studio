# 品牌、通路與材質管理

- 品牌名稱仍存在 `items.brand`／`wishlist_items.brand` 文字欄位；`brands` 只存使用者手動新增的品牌，`brand_distinct_groups` 記錄兩個名稱「不是同一個品牌」。
- 品牌新增、改名、合併、刪除一律走 `replace_brands` RPC（衣物與選購清單一起更新）；復原走 `restore_brand`。
- 品牌相似偵測、排序與日期格式集中在 `src/lib/brands.ts`。
- 購買通路 `shops` 管理包含網路／實體類型與網址；選購候選網址只解析已知網域、不抓網頁，且僅店家欄空白時自動推測。
- 材質 `materials` 支援新增、改名、合併、刪除、隱藏、別名與排序；預設及正規化在 `src/lib/materials.ts`。
- 材質色（B16 色票，用在材質比例的色點與比例條）目前固定寫在 `src/lib/materialMix.ts`：預設材質與常見別名用 B16 的顏色，自訂材質依名稱固定配一個淡色。`materials` 表沒有顏色欄位，管理頁也還不能改色；要讓使用者自訂需新增 migration。
- 對應路由 `/me/brands`、`/me/shops`、`/me/materials`。桌面與手機稿索引見 [design-map.md](../design-map.md)。

## 衣物特徵標籤

- 衣櫃衣物與選購候選共用 `garment_features` 字典及一致名稱；`feature_tags` 以 `{ name, dimension }` 快照存在 `items`／`wishlist_items`，不使用任意 hashtag。
- 固定維度：腰高、褲型／裙型、肩線為單選屬性；質感、細節、場合為多選特徵。維度清單不可自訂；特徵可新增、改名、合併、刪除，並管理別名與適用類型。
- 預設特徵（`FEATURE_DEFAULTS`，每次讀取以 upsert＋忽略重複補進使用者字典，既有資料不覆蓋）：腰高 高腰／中高腰／中腰／低腰；質感 厚磅／磨毛／垂墜／挺版／毛呢；細節 後鬆緊／全鬆緊／打褶／有口袋／開衩；場合 上班／運動／休閒／旅行／約會／雪國（別名 雪地、滑雪）。名稱比對時越靠前的詞優先，所以「中高腰」不會被當成「高腰」。
- 已有部位／類型、長度、顏色、材質、季節欄位不另造同義標籤。預設值由 `src/lib/features.ts` 建立；搜尋名稱只比對已管理的標準名稱與別名，不用 TF‑IDF 或行銷詞推論。
- 表單中的名稱建議以虛線 chip 呈現，尚未確認不儲存；按一下或「全部採用」才寫入。使用者手動移除名稱建議後，把名稱記在 `feature_suggestions_dismissed`，同一筆資料不再提示。
- 特徵選擇器共用於選購表單及衣物新增／編輯；手機先顯示少量 chip，其餘放於可搜尋的 bottom sheet。
- 比較重複判斷先限制同類型，再比較顏色、材質、可取得的長度、單選屬性及多選特徵重疊率。任一方未填的維度跳過，不當成不相同；證據不足時顯示「依據較少」，不顯示百分比。單選屬性兩邊都有值且不同時直接判為「不太像」。
- 衣櫃候選沒有特徵時，比較頁提供連到該衣物編輯表單的「補特徵」入口；儲存後返回比較頁重新計算。
- 路由 `/me/features`；桌面／手機設計稿為 B24、B25、BM21、BM22，見 [design-map.md](../design-map.md)。
